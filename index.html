📘 指标定义与计算逻辑

指标名称定义计算公式
线上预约量 统计周期内，通过线上渠道（官网/APP/小程序）完成新机预约的用户数。 线上预约量 = 预约成功 UV
门店到店量 统计周期内，预约用户实际到店完成核销的数量。 门店到店量 = 到店核销 UV
完成开机量 统计周期内，到店用户中完成新机开机（含联网/账号登录）的数量。 完成开机量 = 开机成功 UV
首次激活量 统计周期内，开机后 7 天内完成首次核心功能激活（如 SIM 卡激活、应用首次使用）的数量。 首次激活量 = 首次激活 UV
门店到店率 预约用户中实际到店核销的比例。 门店到店率 = 门店到店量 ÷ 线上预约量
开机率 到店用户中实际完成新机开机的比例。 开机率 = 完成开机量 ÷ 门店到店量
首次激活率 开机用户中完成首次核心功能激活的比例。 首次激活率 = 首次激活量 ÷ 完成开机量
总转化率 从线上预约到最终首次激活的整体转化效率。 总转化率 = 首次激活量 ÷ 线上预约量
计算示例（2026年7月）：
线上预约 185 万 → 门店到店 152 万（到店率 152/185 = 82.2%）→ 完成开机 138 万（开机率 138/152 = 90.8%）→ 首次激活 128.5 万（激活率 128.5/138 = 93.1%）。总转化率 128.5/185 = 69.5%。

★ 代表案例 · 鸿蒙应用分发全链路

把"看不清的鸿蒙应用分发"——原生与兼容框架双通道——做成一条可追踪、可下钻的健康度链路

背景

华为终端某业务线，鸿蒙应用的上架、下载、安装、更新全流程缺乏统一监控视图，业务决策长期靠人工拉数，滞后且口径不一。

核心挑战

应用分发链路长、环节多，且需在同一看板内同时监控「原生应用」与「兼容框架应用」两条通道——一旦某环节转化异常（如下载骤降、安装失败率升高、异常卸载），无法快速定位责任通道与责任环节。

我的 3 个关键动作
  1. 统一指标口径：定义上架数 / 下载数 / 安装成功率 / 使用数 / 版本升级率 / 卸载率，原生与兼容框架双通道分别对齐，跨部门统一解读。
  2. 搭建总 + 专看板：1 张全链路漏斗总看板 + 5 张专项看板（版本升级率 / 上架进度 / 下载 / 安装 / 使用）。
  3. 多维下钻与预警：支持时间 / 业务线 / 产品线 / 机型下钻，异常波动自动预警。
设计目标与覆盖（脱敏示意）

关键指标定义

统一指标口径，确保跨部门数据解读一致性。

指标 计算口径 说明
应用上架数 统计周期内完成上架的应用数量（去重） 按原生/兼容框架分别统计
下载应用数 统计周期内产生下载记录的应用数量 反映应用市场供给活跃面
安装成功率 安装成功设备数 / 下载完成设备数 × 100% 失败归因：存储/签名/兼容性
应用使用数 统计周期内产生使用记录的应用数量 生命周期核心阶段，衔接安装与更新
激活率 周期内产生使用记录的设备数 / 周期内完成安装的设备数 × 100% 衡量安装后真实使用情况，衔接安装与留存
版本升级率 已升级至最新版本的设备数 / 应升级设备总数 × 100% 仅统计头部应用
卸载率 周期内卸载设备数 / 周期初安装设备数 × 100% 监控异常卸载波动
